# cc-router-mac Anthropic 网关 Spec

## 问题陈述

macOS 用户同时持有多个 Anthropic 兼容上游（官方 API、第三方 Anthropic 兼容端点等），但 Claude Code 这类客户端一次只能配置一个 base URL 和一个 API key。手动切换上游繁琐、易忘，且不同模型往往由不同上游提供，无法在一个会话里混用。

## 解决方案

一个 macOS 菜单栏应用，在本机运行一个 Anthropic Messages 格式的网关：把多个 Provider 聚合为一个本地端点。客户端把 base URL 指向网关即可；网关按模型归属路由把请求转发给命中的 Provider，全程不改写请求与响应（不做协议转换）。界面提供控制网关启停的主开关，以及每个 Provider 的独立启用开关。

## 用户故事

1. 作为 Claude Code 用户，我想要把 base URL 指向本机网关，以便用单一端点使用所有上游
2. 作为用户，我想要网关不校验我发来的凭据（任意 key 放行），以便客户端配置最简单
3. 作为用户，我想要网关按请求中的 `model` 精确匹配各启用 Provider 的模型列表来选择转发对象，以便不同模型自动走不同上游
4. 作为用户，我想要请求的模型不被任何启用的 Provider 声明时收到 Anthropic 格式的 404 `model_not_found`，以便问题定位明确
5. 作为用户，我想要同一模型被多个 Provider 声明时在保存配置阶段即被拒绝并标红冲突项（校验不看启用状态），以便路由表始终无歧义
6. 作为用户，我想要每个 Provider 的模型列表不允许留空（保存时校验拒绝），以便每个 Provider 都有明确的责任范围
7. 作为用户，我想要流式（SSE）响应逐段转发且不中断、不缓冲篡改，以便长输出体验与直连一致
8. 作为用户，我想要 count_tokens 请求透传给命中的 Provider、且上游失败时网关直接返回 `{"input_tokens": 0}`，以便客户端的 token 估算功能永不阻塞会话
9. 作为用户，我想要模型列表接口返回所有启用 Provider 所声明模型的聚合，以便客户端查询网关整体能力
10. 作为用户，我想要网关同等处理带 `?beta=true` 等查询参数变体的路径，以便兼容 Claude Code 的实际调用形态
11. 作为用户，我想要上游返回的 HTTP 错误（含 Anthropic 错误体）原样透传，以便真实看到上游的报错
12. 作为用户，我想要网关自身连不上上游时收到 Anthropic 格式的 502 `api_error`（不重试、不转移），以便错误语义与官方一致
13. 作为用户，我想要客户端请求头原样透传、仅鉴权头被替换为命中 Provider 的 key，以便上游正确收到版本号/UA 等上下文，且我的 key 不外泄
14. 作为用户，我想要用主开关一键启停网关，以便不用时彻底关闭本地服务
15. 作为用户，我想要每个 Provider 有独立的启用开关，以便临时摘除某个上游而不删除其配置
16. 作为用户，我想要在设置窗口里增删改 Provider（名称、base URL、api key、模型列表）并拖动排序，以便维护我的路由表
17. 作为用户，我想要 api key 在界面中掩码显示，以便旁人窥屏不泄露
18. 作为用户，我想要 Provider 配置跨启动持久化，以便不用每次重配
19. 作为用户，我想要 App 启动时恢复上次的主开关状态，以便重启电脑后无操作即恢复服务
20. 作为用户，我想要设置里提供「登录时启动」开关，以便机器开机即自动就绪
21. 作为用户，我想要运行中改动开关与配置立即热生效、不影响在途请求，以便调路由不用停服务
22. 作为用户，我想要在设置中修改监听地址与端口、保存后重启监听、端口被占用时得到明确报错，以便适配本机环境
23. 作为用户，我想要网关对未识别的路径返回 404，以便行为可预期
24. 作为用户，我想要菜单栏常驻一个静态图标、点击弹出 popover 开关面板，以便随时查看与切换状态

## 约束

- macOS 原生应用，Swift + SwiftUI。
- 只聚合、不转换：所有上游均为 Anthropic 兼容格式；网关不改写请求/响应体，不改写 `model` 名，不做任何 Anthropic ↔ 其他协议的映射。
- 兼容 Claude Code 的实际调用形态：`/v1/messages`、`/v1/messages/count_tokens` 的 `?beta=true` 变体、`/v1/models` 的 `?limit=1000` 变体均须容忍。
- 单 Provider 单 key（不做 key 池）。
- 监听默认 `127.0.0.1:8317`，默认仅本机可达。

## 范围外

- 协议转换（OpenAI 等其他格式 ↔ Anthropic）
- 故障转移、重试、负载均衡、轮询
- 同一 Provider 多 key / key 池轮换
- `GET /v1/models/{model_id}` 模型详情端点
- 客户端侧鉴权校验（明确放行任意 key）
- 请求日志查看器、用量/计费统计
- 模型名通配符、别名映射
- 网关对 OAuth、`/v1/me` 等 Anthropic 第一方端点的转发（这些流量不会到达自建网关）

## 补充说明

- 本 spec 来自 2026-10-23 的需求澄清访谈共识；领域术语见根目录 CONTEXT.md（Provider、模型归属路由、主开关）。
- 端点事实依据：对本机 Claude Code v2.1.309 二进制的静态分析——`count_tokens` 位于其核心路径白名单（常规会话真实调用）；`/v1/models` 仅在网关模型发现模式下被调用且失败可优雅跳过；OAuth/账户类流量仅对 Anthropic 第一方主机发送，自建网关不可见。
- 端口默认值 8317 为访谈推荐值，无历史包袱，实现时可微调（属技术方案自由度）。
