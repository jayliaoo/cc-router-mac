# 07: 设置窗口 + 登录自启

**做什么：** Provider 的增删改排序有了正式的家：设置窗口（表单 + 掩码 + 校验标红）、监听地址端口修改（重启监听）、「登录时启动」开关。完成后 spec 的 24 条用户故事全部可用，产品功能收口。

**阻塞于：** 06（app 壳与菜单栏 UI 就绪）。

**状态：** 完成（手测项留待发起人验收）

## 上下文

- **相关用户故事**：spec 5（重复模型保存时拒绝并标红）、6（空列表校验拒绝）、16（增删改排序）、17（api key 掩码）、20（登录时启动）、21（热生效）、22（地址端口修改后重启监听、占用报错）。
- **设计决策**（自 design 摘录）：
  - 设置窗口（菜单栏 popover 内「设置…」入口打开的独立窗口）：
    - Provider 列表：**可拖动排序**（顺序仅 UI 展示，路由不依赖它——重复模型已被校验杜绝）、增加、删除、编辑。
    - 编辑表单：名称、baseUrl、apiKey、模型列表（一行一个模型名，精确匹配，无通配）；**apiKey 输入框掩码显示**。
    - 校验错误**标红定位**（消费 ConfigStore 任务 02 的校验错误信息）：空模型列表、跨 provider 重复模型（与启用状态无关）、非法 URL、空 apiKey、重复 id；保存被拒绝时配置与内存快照不变。
    - 监听地址/端口编辑：保存后**重启监听**生效；端口占用 → 明确报错、主开关回落 off（沿用任务 06 的报错通道）。
  - 登录自启：**SMAppService.mainApp**（macOS 13+ 系统标准 Login Item API），设置窗口内的开关；开启后 App 启动恢复主开关状态（任务 06 已实现），即登录即网关就绪。
  - 所有改动经 ConfigStore 快照交换热生效，在途请求不受影响；配置改动持久化落盘。
- **seam 约定**（design「6.2」）：UI 手工验证，不新增自动化 seam；校验/持久化逻辑已被任务 02 单测覆盖，本任务只做 UI 接线。
- **术语**：Provider 定义见根目录 CONTEXT.md（名称、base_url、api_key、模型列表、启用开关、顺序）。
